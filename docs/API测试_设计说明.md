## 1. 总体架构

API 测试由页面运行配置、项目资源页面、后端业务接口和执行服务共同组成：

```text
API 测试页面
  ├─ 项目与环境
  ├─ 接口目录与接口详情
  ├─ 接口用例与参数集
  ├─ 执行集与测试报告
  └─ 运行配置：当前环境、当前参数集
          │
          ▼
FastAPI 业务接口
  ├─ 项目范围和资源归属校验
  ├─ 接口导入与预览
  ├─ 接口调试与用例执行
  ├─ 执行集、报告和调度
  └─ 通知、审计和统一响应
          │
          ▼
MySQL + 外部被测服务
```

运行环境和参数集由项目页面的统一运行配置提供。接口调试、单条用例运行和执行集运行都读取当前配置，不在页面之间维护互相独立的运行配置。

## 4. 标准接口导入

标准导入入口为 `POST /api/v1/import/parse-file` 和 `POST /api/v1/import/execute`，支持：

- OpenAPI 3.x；
- Swagger 2.0；
- Postman Collection v2.1；
- Excel 接口清单（`.xlsx`）。

处理流程：

1. 页面上传文件，后端校验扩展名、编码和大小；同一步里选择导入到哪个接口集，并可选一个服务标识。该接口集只决定新接口的落库位置，文档里的模块作为它下面的二级目录；已有接口不受影响。服务标识只记在接口上，接口地址按文档原样保留，不在导入时剥掉服务前缀——运行时由环境按服务解析。导入接口资产不依赖是否已选择运行环境；运行环境只负责提供可选服务标识和后续运行时解析条件。
2. 解析器将不同格式转换为统一的模块和接口结构。
3. 页面展示模块、目录和接口预览，导入模式在这一步选择。两种模式的落库口径完全一致——新增接口导入、有变化的已有接口原地更新、完全一致的接口跳过——模式决定后端返回哪些预览行：“全量模式”返回文件中的全部接口，无变化的行标注「无变化，不导入」；“增量模式”只返回新增和有变化的接口。解析后调用 `/check-duplicates`，切换模式会携带不同的 `import_mode` 重新请求，前端不再按判重结果自行过滤。预检会在项目范围内认出已有接口，并按名称、地址、请求方法、请求参数四项判断有没有变化；接口集不参与。不落库的接口在概览里说明条数与原因。每条结论带按提交顺序递增的 `index`，前端按同样顺序把结论对回行——不要改用目录名拼键，用户在预览页改目录后就对不上了。
4. 后端按项目权限执行保存；有变化的老接口原地更新原来那条，`collection_id` 一律不动；完全没有变化的接口既不更新接口，也不创建或更新用例。文件导入默认只保存接口，用户勾选“生成基础用例”后才处理基础用例；目标接口集在确实要新建接口时才解析或创建，避免整批都是老接口时凭空多出空接口集。
5. 导入结果返回 `unchanged_interfaces`（完全一致、未导入），不再使用含糊的“跳过”口径，并写入操作记录。`preserved_interfaces` 是「有变化但按老增量口径保留」的历史字段，当前两种模式都会更新有变化的接口，该值恒为 0，仅为兼容保留。文档里已经不存在的老接口不做任何处理。

标准导入的解析缓存只保留有限数量的近期结果；URL 解析入口当前明确返回“URL 导入暂未开放”，不应在文档中描述为可用能力。

解析交互约定：点击解析后，在当前导入弹窗内显示居中的加载遮罩并禁用重复操作。文件扩展名、编码、整体结构或大小错误属于文件级错误，阻断当前文件并在弹窗内展示原因；单个接口的请求体格式错误属于接口级错误，解析结果同时返回成功接口和失败接口，失败项展示接口名称及“请求体格式错误，请检查后重新上传”。存在成功接口时允许进入下一步，但下一步只展示成功接口，失败接口不会被静默导入；全部接口失败时停留在错误结果状态，不进入空的下一步。

## 5. 接口状态、用例确认和 AI 生成

接口导入后维护“待处理 / 已处理”状态以及“新增接口 / 请求定义变化 / 存量数据待确认”原因。文件导入负责接口定义的新增、原地更新、状态标记以及用户主动选择的基础用例处理；请求定义变化时保留已有用例名称、断言、脚本和用户填写内容，仅同步必要的请求地址、方法及参数结构，并将关联用例设为“待确认”。

接口列表支持按状态和用例数查询，也支持用户批量标记接口状态；待处理原因只在列表和接口信息中展示，不单独提供筛选项。勾选接口或生成用例不会自动改变接口状态。

接口列表的批量“AI生成用例”和接口用例页面的单接口“AI生成用例”共用同一套五步向导、预览暂存和保存事务。接口列表入口第一步按接口集、“名称或 URL”统一搜索、状态和用例数筛选，支持服务端分页及跨页全选；接口用例页面入口第一步只放入当前接口，生成范围固定为 1 条。第 2 步点击“开始生成”后自动进入第 3 步，失败时展示接口级失败原因并支持返回调整或重试，成功后进入第 4 步；用户勾选并保存成功后才进入第 5 步。选中已有用例的接口时先二次确认，保存阶段按实际请求意图跳过重复结果，AI 生成的新用例保存为“待确认”，确认、调试和执行在用例管理中分别完成。文件导入可选生成基础用例，但不调用 AI。API 测试模块的列表、树、弹窗明细和统计区域统一使用暂无数据样式；单接口表格按内容自适应高度，不显示多余的纵向滚动条，多条数据超出最大高度时仅表格正文区域滚动并保持表头固定，横向滚动条固定在对应滚动区域底部。接口编辑及用例编辑页面的名称和描述输入框均限制为 50 个字符，并显示字数提示。

应用重复启动时只补齐缺失的状态字段和存量默认值，不覆盖已经标记为已处理或已确认的记录；导入或接口定义变化导致的业务状态调整仍按对应业务规则执行。接口复制请求在完成前禁止重复提交，成功提示只使用后端返回的消息。

## 6. 运行时数据流

一次接口用例运行的基本顺序为：

1. 校验项目、接口用例、环境和参数集都属于当前项目且未删除。
2. 读取当前运行环境，解析基础 URL、服务路径前缀、认证、代理和全局请求头。
3. 合并参数集、接口定义和用例级覆盖，生成本次请求数据。
4. 执行前置脚本，发送 HTTP 请求。
5. 执行响应校验、断言和后置脚本，收集请求、响应、日志、耗时和错误信息。
6. 单条运行返回运行结果；执行集运行将步骤结果写入报告和报告明细。

有启用断言时，默认按业务码断言控制：读取响应 JSON 顶层 `code`，与 `200` 比较时兼容数字和字符串；非 JSON 或缺少 `code` 判定该断言失败。用户可以编辑或明确关闭默认断言，关闭后不再执行该业务码校验；历史用例不批量补写默认断言。没有启用断言时，接口调试、单条用例和执行集统一使用 HTTP status code 判断成功：`2xx` 为成功，其他状态为失败。

服务配置的运行时解析遵循“用例显式配置 → 接口配置 → 不使用服务”的顺序。环境中的服务路径前缀和认证按本次运行实时读取，修改环境后无需重新保存接口。

### 6.1 参数集详情与参数化

参数集列表页面使用参数集列表接口进行分页查询；名称条件只有点击“查询”后才提交，页面默认请求 10 条，支持 10、50、100 条。参数集选择器等需要获取候选集的场景可以请求更大范围的候选数据，不改变列表页的分页口径。

参数集详情的参数项列表通过参数集 ID 查询，服务端同时处理参数名称、Key、Value 条件、偏移量和页大小，并返回当前页数据和总数。前端切换页码或页大小时重新请求；新的查询条件提交后回到第一页。

参数项删除分为单项删除、当前页选中项批量删除和当前筛选范围全部删除。全部删除的范围固定为“当前参数集 + 当前已提交筛选条件”，不能扩展到其他参数集或未命中的参数项。删除前由后端检查引用；确认删除后，参数项软删除与接口、用例中的引用恢复在同一事务内完成。恢复值使用删除操作发生时参数项的当前 Value，JSON 等结构化值同时传递原类型，避免把对象或数组恢复成字符串。

参数化检索通过参数集搜索接口执行，支持按参数值、Key、类型和来源关键字筛选；来源关键字匹配接口 URL、接口名称或用例名称。识别可复用参数支持按查询参数、路径参数、请求体、请求头多选筛选，默认选中前三类，请求头需主动选择，“全部（含请求头）”表示四类位置全部纳入；位置筛选由后端执行，结果统计和来源明细同步变化。位置筛选允许为空，空筛选由后端直接返回空结果，不回退到默认位置。结果返回接口和用例的命中位置，前端按接口聚合并在接口下展示相关用例；该来源列表不分页。接口和用例统一使用“参数位置：查询参数/路径参数/请求体/请求头”标签说明替换位置；用例行必须保留用例类型、用例名称和“打开详情”入口，随后展示原值到参数名的替换关系。Key 相同但值不同的命中进入异常项，不默认勾选；单接口结果默认展开，多接口结果默认收起。

识别可复用参数弹窗的主列表只保留参数名称、Key、类型和值等编辑字段；来源、位置、创建来源和来源值放入可展开的来源明细，来源明细中的接口或用例名称可打开对应详情。

参数化替换只修改用户确认的目标字段；去参数化使用参数项当前值恢复原字段，并按字段原类型写回。删除参数项时复用同一去参数化逻辑，确保接口或用例不会保留 `$.key` 失效引用。

参数化弹窗允许在参数分组中临时修改 Value 和类型。点击“重新识别”后，系统按新的 Value 和类型重新计算命中结果：已参数化项仍按当前参数引用归入已参数化，去参数化时使用修改后的参数值和类型恢复；值或类型不匹配的命中归入异常项且不默认勾选。修改结果不会立即写入，只有点击“执行替换”或“执行去参数化”时，参数设置与选中的替换在同一批操作中保存；关闭弹窗则放弃未执行的修改。参数设置更新和替换分别写入审计日志，校验失败原因写入服务端错误日志。

## 7. 执行集、报告和调度

执行集保存以下运行配置：

- 目标测试用例及执行顺序；
- 运行环境和可选参数集；运行环境为必填配置，新建或编辑时未配置、未选择环境统一返回“请配置或者选择运行环境”；
- 串行或并行执行方式；
- 失败重试次数；
- 手动触发或定时触发；
- 消息渠道和消息模板。

执行集运行时：

- 每个执行集生成一份测试报告；
- 报告保存总用例、通过数、失败数、通过率、耗时和执行方式；
- 报告明细保存每一步的请求、响应、断言、脚本日志、差异结果和错误信息；
- 定时触发写入调度运行日志；
- 报告发送写入报告发送日志；
- 定时任务正在运行时，重复触发按策略跳过并记录原因。
- `retry_count` 取值范围为 0～3；设置为 3 时首次执行 1 次，最多重试 3 次，总计最多 4 次。
- 测试报告最终为失败时，本次调度运行日志同步记为失败；本次失败不会阻止下一次调度。

接口调用约定中，运行环境在业务上是必填字段。请求结构允许为空仅用于让后端返回统一的业务提示；调用方仍必须传入当前项目中存在且未删除的运行环境，不能将结构层的可空理解为业务可选。

执行集列表查询接口按 `created_at` 倒序、再按 ID 倒序稳定排序；ID 仅用于内部操作和路由，列表不向用户展示。测试报告详情使用按用例聚合的明细查询接口，服务端按用例名称、状态和接口集筛选，并对用例分组分页；展开用例后再展示该用例下的步骤明细。展开的用例标题在详情滚动区域内保持可见，响应体等长文本在自身区域内滚动，并限制响应区域高度，避免详情内容无限撑高页面。

## 8. 权限和安全边界

权限必须在项目范围和具体资源两层校验：

- 项目创建人和超级管理员可以管理各自授权范围内的项目及资产。
- 管理员可以管理公开项目内的 API 业务资产，以及本人创建的项目。
- 清空项目数据属于高风险项目级操作：仅超级管理员可清空全部项目，私有项目创建人可清空本人项目；公开项目创建人、管理员和普通用户不可执行。
- 普通用户对公开 API 项目以查询为主，不能仅因可见就获得资产写入、环境凭证使用或外部请求执行权限。
- 普通非项目创建人可以查看接口、用例、执行集和报告列表，以及报告统计汇总；不能查看接口、用例、环境和报告详情，也不能执行或调试。
- 项目、环境、接口、接口集、用例、参数集和执行集的 ID 必须在后端验证归属，不能只信任页面传值。
- 环境 Token、请求头、API Key、Cookie、密码和 Webhook 密钥等内容必须按权限返回：普通非项目创建人不能进入相关详情，项目创建人、管理员和超级管理员在授权范围内可以查看完整内容。
- 接口调试和执行前应确认当前环境，避免误请求生产环境。
- 执行集保存必须有有效的当前项目运行环境；缺少环境或环境不属于当前项目时，前端先提示，后端继续做归属和存在性校验。
- 清空项目数据中，前端选择接口时必须联动选择并锁定用例；取消接口时同步取消用例，但用例可以在未选择接口时单独清理。接口清理级联软删除关联用例和执行项，成功提示使用实际清理数量。
- AI 预览和正式保存分开判断权限，AI 生成结果不能绕过项目写入权限；文件导入和 AI 生成用例分别执行，不在导入流程内混合生成。

完整角色矩阵见 [权限说明.md](权限说明.md)。

## 9. 统一实现约定

- 平台管理接口使用统一的 `code`、`message`、`data` 结构，HTTP 状态固定为 200，不用 HTTP 状态表达平台管理接口的业务成功或失败；对被测接口而言，无启用断言时按 HTTP `status_code` 判断，`2xx` 为成功，其他状态为失败。
- 查询条件点击“查询”后才发起请求，查询后回到第一页。
- 列表默认分页 10 条，支持 10、50、100 条。
- 表格表头禁止换行，长内容使用省略号并保留查看完整内容的入口。
- 操作列固定右侧，按钮不换行；页面整体不出现横向滚动。
- 删除、批量删除、清理和可能产生额度消耗的重试需要二次确认。
- 错误提示以服务端中文 `message` 为准，同一错误只提示一次。
- 所有时间按北京时间展示，不展示 ISO 格式时间。

## 10. 验证重点

API 测试相关改动至少验证以下场景：

1. 项目、环境、接口、用例、参数集和执行集跨项目访问均被后端拦截。
2. 标准导入四种文件格式均能完成解析预览，URL 导入返回未开放提示。
3. 导入预览未确认前不写入正式接口和用例。
4. 当前环境和参数集能同时作用于接口调试、单条用例运行和执行集运行。
5. 参数集列表和参数项列表的查询条件、分页总数、当前页切换保持一致；批量删除与全部删除范围正确，删除引用参数后不残留失效变量。
6. 串行、并行、重试、报告明细、定时日志和消息发送记录口径一致；报告详情筛选、分组分页和展开步骤结果一致。
7. 普通用户无法通过直接构造请求使用公开项目凭证或执行外部请求。
8. 失败、空结果、无权限和数据不存在等情况不会被伪装成成功或空数据。
9. API 测试数据清空的预览与执行均校验高风险项目权限：超级管理员可操作全部项目，仅私有项目创建人可操作本人项目，其他身份统一返回“权限不足”。
10. 清空项目数据选择接口时用例自动选中且置灰，取消接口时用例同步取消；只选择用例时不影响接口；预览和成功提示中的用例数量与实际软删除数量一致，执行集中的同一用例只计一次。
11. 新建和编辑执行集未配置或未选择运行环境时，前端显示红色必填提示；绕过前端直接请求时，后端返回“请配置或者选择运行环境”，环境不属于当前项目时返回归属错误。
12. 测试报告展开用例后滚动详情区域，用例标题仍可见；响应体超长时仅响应区域出现上下、左右滚动，不撑高整个页面。
13. AI 生成用例连接能持续收到探活，并在完成后正常收到最终结果；取消请求后服务端任务能停止，已完成批次仍保留。
14. 需要单独确认集群的超时类型：若是请求总时长限制，不能把流式探活当成最终解决方案，应转为后台任务方案。
