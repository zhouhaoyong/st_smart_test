# 管理中心技术架构与数据设计

> 文档视角：当前实现、技术架构、权限校验和数据流。
>
> 产品功能和用户流程以 [管理中心_产品说明.md](管理中心_产品说明.md) 为准；全平台权限以 [权限说明.md](权限说明.md) 为准。
>
> 文件名沿用项目现有命名 `desgin`。

## 1. 总体架构

管理中心由前端页面、统一请求层、FastAPI 管理接口、业务服务和 MySQL 数据组成：

```text
管理中心页面
  ├─ 个人中心
  ├─ 平台用户管理
  ├─ AI 模型配置与用量统计
  ├─ 消息渠道、消息模板与执行策略
  ├─ 问题反馈
  └─ 审计日志与平台数据管理
          │
          ▼
统一请求与响应处理
  ├─ 登录认证
  ├─ 中文错误提示和单次 Toast
  ├─ 分页、查询和删除操作
  └─ 敏感字段展示控制
          │
          ▼
FastAPI 管理接口
  ├─ 当前用户认证
  ├─ 角色和数据范围校验
  ├─ 业务服务、软删除和审计
  ├─ AI 模型路由、额度和能力检测
  └─ 消息配置、执行策略和数据清理
          │
          ▼
MySQL
```

HTTP 状态统一为 200，业务结果通过 `code`、`message`、`data` 表达。前端菜单、路由和按钮只负责入口体验，后端接口必须再次完成权限校验。

## 2. 页面与接口入口

| 页面 | 前端路由 | 当前访问范围 | 主要接口范围 |
| --- | --- | --- | --- |
| 个人中心 | `/profile` | 全部登录用户 | `/auth/profile`、`/auth/password` |
| 平台用户管理 | `/users` | 超级管理员 | `/users/` |
| AI 模型配置 | `/model-admin/models` | 全部用户；用户模型页仅超级管理员 | `/ai/models`、`/ai/quotas` |
| AI 用量统计 | `/model-admin/usage` | 全部用户，数据范围不同 | `/ai/usage` |
| 消息渠道管理 | `/config-admin/channels` | 管理员、超级管理员 | 消息配置接口 |
| 消息模板管理 | `/config-admin/templates` | 管理员、超级管理员 | 消息配置接口 |
| 执行策略管理 | `/config-admin/policies` | 管理员、超级管理员 | 执行策略接口 |
| 问题反馈 | `/feedback` | 全部登录用户 | 反馈接口 |
| 审计日志管理 | `/data-admin/audit` | 超级管理员 | 审计接口 |

历史设置路由和旧模型入口只承担兼容重定向，不作为当前管理中心主菜单或独立业务页面。

## 3. 角色和权限实现

### 3.1 角色判定

当前用户通过用户表中的布尔字段判定：

| 展示角色 | 判定条件 |
| --- | --- |
| 超级管理员 | `is_superuser = true` |
| 管理员 | `is_superuser = false` 且 `is_manager = true` |
| 普通用户 | `is_superuser = false` 且 `is_manager = false` |

部门只表示用户的组织归属，用于筛选、统计和业务展示，不参与角色推导。公开注册用户默认为普通用户；后台新增用户时由超级管理员明确选择角色，修改部门不会自动改变已有角色。管理员角色与超级管理员角色互斥，系统至少保留一个启用中的超级管理员，当前登录的超级管理员不能自我降级、禁用或删除。

### 3.2 管理中心权限边界

- 个人资料和密码只允许当前用户维护。
- 平台用户、审计日志和平台数据管理仅超级管理员可访问。
- 平台模型仅超级管理员可以创建、编辑、启停和删除；所有用户可以查看满足可见条件的平台模型。
- “我的模型”由模型所有人管理；超级管理员查看他人的“我的模型”时为只读。
- 消息渠道、消息模板和执行策略由管理员及以上角色管理。
- AI 用量和调用记录普通用户、管理员只能查看本人，超级管理员可以查看全量。
- 项目权限不在管理中心重新定义，业务模块统一遵循 [权限说明.md](权限说明.md)。

前端根据角色控制菜单、路由和操作按钮；后端在每个敏感接口中重新判断角色、模型归属、数据范围和资源状态。

## 4. AI 模型和额度

### 4.1 模型范围

模型表通过 `scope` 区分：

- `platform`：平台模型，由超级管理员维护，供有权限的用户使用；
- `personal`：个人模型，由创建人或所有人维护。

模型创建时由服务端确定范围，创建后不能通过更新请求改变范围。模型所有人优先使用 `owner_user_id`，兼容读取时可回退到 `created_by`。

### 4.2 模型查询

模型列表按三个页签查询：

1. `mine`：当前用户的个人模型；
2. `platform`：可见的平台模型；
3. `users`：其他用户模型，仅超级管理员可访问。

列表接口不返回完整 `base_url`、请求头或余额内容。编辑和详情接口在权限允许时返回完整接口地址；API Key 只返回是否存在或脱敏值，不返回明文。

### 4.3 模型候选和明确选择

业务 AI 调用通过独立的候选查询获取模型。候选必须同时满足：

- 当前用户可见；
- 已启用；
- 未因账号或权限变化失效；
- 已配置有效额度；
- 当前额度仍有剩余。

平台模型按模型 ID 升序排在个人模型之前，顺序只用于展示推荐。真正调用时必须携带用户明确选择的模型 ID，服务端不按候选顺序自动调用、自动降级或静默切换。

### 4.4 额度和调用记录

- 平台模型使用平台共享日额度，超级管理员调用平台模型不受平台额度限制。
- 个人模型使用 `ai_user_model_quotas` 中按用户和模型设置的日额度。
- 有效额度必须为正整数；未配置额度不使用 0 代替。
- 模型检测和余额查询不写入 AI 调用消费记录。
- AI 调用结果和额度消费独立记录：成功、失败由业务结果判断，是否扣费由实际调用状态判断。
- 超时、网络中断等已经发起但无法确认结果的调用按失败记录，并按当前实现计入消费。
- 明确的调用前余额不足、鉴权失败、接口不存在或限流拒绝，且没有返回模型内容时不扣消费。

用量查询按角色限定用户范围。今日统计使用北京时间自然日；历史日期或时间段只返回该范围的成功、失败和扣费次数，不虚构历史额度上限。

### 4.5 模型能力检测

模型能力检测一次判断连通性、思考模式和用量返回能力：

```text
发起检测 → 保存当前模型能力状态 → 写入检测历史 → 返回展示结果
```

检测状态只用于展示和配置参考，不自动决定模型能否启用，不触发业务 AI 调用，也不消耗平台 AI 额度。新建或编辑未保存模型时，检测结果随表单保存；已保存模型的检测结果写入模型和检测历史。

## 5. 消息配置和执行策略

### 5.1 消息配置

消息配置由三类数据组成：

| 数据 | 作用 |
| --- | --- |
| `message_channels` | 保存钉钉、飞书、企业微信和 Webhook 渠道配置。 |
| `message_templates` | 保存模块、事件类型、正文和变量。 |
| `message_bindings` | 将事件、模板和渠道建立绑定关系。 |

渠道地址、签名密钥和其他敏感字段在列表与日志中脱敏。编辑时由后端按管理权限返回可编辑内容，密钥不返回原文，未重新填写时保留原配置。发送测试消息和配置变更写入审计。

### 5.2 执行策略

执行策略支持按日、按周、间隔和 Cron 配置。`schedule_policy_bindings` 将策略绑定到具体业务目标，`api_schedule_run_logs` 保存触发、执行、跳过和消息状态。

策略运行遵循：

```text
加载启用策略 → 查询绑定目标 → 触发执行 → 写入运行日志 → 发送通知
```

同一目标仍在执行时，后续触发按当前策略跳过并记录原因；停用或删除策略不会删除历史运行日志。

普通用户在本人创建项目的执行集创建或编辑过程中可以选择已有执行策略，但选择器只返回策略名称和启用状态，不返回调度表达式及其他管理配置。管理员和超级管理员在管理权限范围内查看完整策略配置。

调度运行日志的执行状态以测试报告最终状态为准：报告成功记为成功，报告失败记为失败；系统异常也记为失败并保留异常原因。失败只影响本次运行，不会永久阻止后续调度。执行集的 `retry_count` 允许 0～3，`3` 表示首次执行 1 次并最多重试 3 次，总计最多 4 次。

## 6. 用户、反馈、审计和数据治理

### 6.1 用户和模型状态联动

用户停用或软删除后，其个人模型会被标记为失效并停止参与后续调用。恢复用户状态不会自动恢复已经失效的模型，需要具备权限的人员显式启用。

### 6.2 问题反馈

反馈记录保存提交人、类型、标题、内容、页面路径、截图、处理状态、管理员回复和处理时间。普通用户只查看自己的反馈，管理员及超级管理员处理全部反馈。反馈操作与状态变化保留必要的审计信息。

### 6.3 审计日志

审计日志记录用户管理、模型配置、额度变更、模型检测、余额查询、消息配置、执行策略和数据清理等关键操作。日志按条件分页查询；按条件批量删除时，后端使用最近一次提交的筛选条件，不使用前端二次过滤结果。

### 6.4 平台数据清理

平台数据清理仅开放给超级管理员。清理流程为：

```text
读取系统允许清理的数据范围 → 预览数量和内容 → 二次确认 → 物理清理软删除数据 → 写入审计
```

预览失败不能伪造数量。预览默认展示全部允许治理的表，也可以按表名和中文名称筛选；执行时仅清理当前查询结果中的表，清理条件以当前截止时间或清理天数为准。表范围由后端固定元数据校验，敏感字段不直接返回。

| `ai_usage_logs` | AI 调用、结果和消费记录。 |
| `ai_model_detection_logs` | 模型能力检测历史。 |

## 8. 统一实现约定

- 所有管理接口使用统一的 `code`、`message`、`data` 响应结构。
- 查询条件必须点击“查询”后才发起请求，查询后回到第一页。
- 列表默认分页 10 条，支持 10、50、100 条。
- 表格表头不换行，长内容使用省略号并支持查看完整内容。
- 操作列固定右侧，按钮不换行，页面主体不出现横向滚动。
- 删除、停用、清理和可能产生 AI 消耗的重试均需要二次确认。
- 错误信息以服务端中文 `message` 为准，同一错误只提示一次。
- 所有时间按北京时间展示，不展示 ISO 格式时间。
- 所有软删除数据默认不出现在业务列表中，历史审计和调用记录按权限保留。

## 9. 实现边界

- 管理中心不新增项目成员模型，业务项目权限沿用平台统一权限规则。
- 模型权重和功能分配不属于当前实现，不能在文档中描述为可配置能力。
- 普通用户和管理员不能通过地址、接口参数或构造请求访问超级管理员数据。
- API Key、Token、Cookie、密码和 Webhook 密钥不以明文写入列表、日志或错误提示。
- 任何前端隐藏都不能替代后端鉴权；后端拒绝后前端只展示一次错误提示。
