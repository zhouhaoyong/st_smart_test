# API 测试产品说明

## 1. 这套功能解决什么问题

API 测试用于把接口从“只能单独调用”变成“可以统一管理、反复验证、批量执行和追踪结果”。

使用它可以完成：

- 管理项目、环境和接口；
- 导入已有接口资料，减少重复录入；
- 调试单个接口，确认地址、参数、请求和响应是否符合预期；
- 把接口保存为测试用例，重复执行并保留结果；
- 使用参数集批量验证不同数据；
- 查看执行报告，定位失败原因；
- 使用 AI 辅助生成测试用例。

这份说明面向实际使用者。接口权限的完整矩阵见 [权限说明](./权限说明.md)，页面设计约定见 [API 测试设计说明](./API测试_设计说明.md)，AI 功能的详细说明见 [API 测试 AI 能力说明](./API测试_AI能力说明.md)。

## 2. 谁可以使用

| 使用者 | 可以做什么 |
| --- | --- |
| 项目创建者 | 管理项目、环境、接口、用例、参数集和执行记录 |
| 项目管理员 | 按项目权限管理和维护测试内容 |
| 普通成员 | 查看有权限的内容，并按授权范围调试、执行或维护内容 |

项目是否公开，决定其他人能否看到项目；公开不等于所有人都可以修改或执行全部内容。涉及真实数据、授权信息或敏感接口时，应使用私有项目，并为成员分配必要的权限。

## 3. 使用前需要理解的几个概念

| 概念 | 说明 |
| --- | --- |
| 项目 | 一组相关接口、环境、用例和执行结果的工作空间 |
| 环境 | 接口运行时使用的地址、变量、请求头、令牌等配置 |
| 接口 | 可以被调试或执行的一条请求定义 |
| 接口目录 | 按文件夹或业务模块组织接口 |
| 测试用例 | 在接口基础上补充测试数据、断言和脚本后的可重复测试 |
| 参数集 | 一组可重复使用的输入数据，用于一次测试多组场景 |
| 执行集 | 一批需要连续或批量执行的测试用例 |
| 测试报告 | 对一次执行的结果、请求、响应和失败信息的汇总 |

一个典型的使用路径是：

创建项目 → 配置环境 → 导入或新建接口 → 调试接口 → 保存测试用例 → 执行测试 → 查看报告。

## 4. 从零开始完成一次接口测试

### 4.1 创建项目

创建项目时填写项目名称和说明，并决定项目是公开还是私有。

建议：

- 团队协作、需要让成员查看的项目，可以公开；
- 含有内部地址、令牌或真实业务数据的项目，建议私有；
- 不要把真实令牌、密码或其他敏感信息直接写进接口说明、参数集或文档内容。

### 4.2 配置环境

环境用于保存一组运行条件，例如：

- 接口服务的基础地址；
- 不同环境使用的变量；
- 公共请求头；
- 身份认证信息；
- 代理或服务相关设置。

调试或执行前需要选择环境。环境只提供运行时条件，不会自动把接口复制到其他环境；切换环境后，应确认地址和认证信息是否正确。

### 4.3 导入或新建接口

可以通过以下方式准备接口：

- 手动填写请求方法、地址、参数、请求头和请求体；
- 导入 OpenAPI、Swagger、Postman 或 Excel 等接口资料；
- 通过单条 cURL 命令导入一个接口；
- 在工具箱中使用 cURL 解析功能临时查看或运行一条命令。

文件导入后会先展示解析结果，确认后才保存到项目。点击解析时弹窗内会显示加载状态；文件整体格式、编码或大小错误会阻止继续，单个接口请求体格式错误会在弹窗内列出接口名称和错误原因。只要仍有解析成功的接口，就可以进入下一步并只处理成功接口；全部接口失败时不能进入空的下一步。失败接口修正后重新上传即可。

文件导入和 cURL 导入都在弹窗内选择导入到哪个接口集，可以选已有的，也可以按层级新建；不需要先在左侧点中接口集。第一步选的接口集只决定**新接口**放在哪，文档里的模块会成为它下面的二级目录；平台上已经有的接口一律留在原位，不会因为导入换位置。文件导入可以按需生成基础用例，但不调用 AI；需要 AI 生成用例时，可以在接口列表批量选择接口，或进入接口用例页面后针对当前接口使用“AI生成用例”。

接口管理中的 cURL 导入按项目保存，不要求先选择运行环境。选择环境时，环境中的服务列表只用于提供候选服务标识；未选择环境时仍可手填服务标识，也可以留空。非空服务标识按“请求方法 + 地址 + 服务标识”匹配，留空时只匹配同样没有服务标识的接口，避免不同服务之间误覆盖。

“AI生成用例”使用一个五步向导完成：选择接口、生成模式、生成中、预览确认、保存成功。接口列表入口可以批量选择接口；接口用例页面入口只针对当前接口，第一步默认展示这一条且不能扩展范围。第 1 步使用“下一步”，第 2 步使用“开始生成”；第 3 步自动展示生成进度，失败时显示具体失败原因并支持返回调整或重试；第 4 步允许预览、编辑和勾选用例后使用“保存新增用例”，只有保存接口成功才进入第 5 步“用例保存成功”。除保存成功终态外，已展示的人工操作步骤均提供“上一步”；生成中的请求不提供返回按钮，避免中断请求造成状态混乱。向导不会因为打开或切换步骤直接修改接口和已有用例。

导入模式（全量 / 增量）放在第二步，也就是解析完、看得到有多少已有接口之后再选；切换由服务端按当前项目重新计算结果，不在前端猜测。

重复接口的识别口径三处一致，而且「认出是同一个接口」和「判断它有没有变化」是两套规则，不要混在一起看。认接口只在整个项目范围内做：来源带接口编号时优先按编号，否则按地址加请求方法。认出来之后，再比较名称、地址、请求方法、请求参数这四项，任意一项和文档不一样就算有变化；响应结构、请求头，以及接口所在的接口集一律不参与。

识别到已有接口时一律更新原来那条，不会在别处再建一条重复的：改了名称就更新名称，改了地址就更新地址，改了参数就把参数补上去。文档把接口归到了别的模块也不会把它搬走——接口留在你现在放它的位置，预览页里这类接口的目录列显示「保持原位」且不可修改，只有新增接口可以选目录。已有用例只补充新参数（含请求体新增的字段），新补的内容只补结构、取值留空，你自己填过的取值不会被覆盖，断言和用例名也不动；只有请求地址、请求方法、请求体类型这三项会以文档为准覆盖回去。

文档里已经不存在的老接口不做任何处理，接口和用例都原样留着。四项都没变的接口同样什么都不动：不导入，也不创建或更新用例。两种模式的导入结果完全一致，模式只决定这类接口在第二步列表里露不露面——全量模式列出来但不导入，增量模式直接隐藏；不管选哪种，第二步顶部都会告诉你共解析多少个接口、其中新增多少、有变化多少、无变化不导入多少。

这里有一个容易混淆的区别：

- 接口管理中的 cURL 导入，用于把一条命令整理成项目中的接口；
- 工具箱的 cURL 解析，用于快速解析、检查并直接运行一条命令，不会自动把内容保存成项目接口或测试用例。

### 4.4 调试接口

调试前选择环境，检查请求方法、地址、参数、请求头和请求体，再点击调试。

调试结果重点关注：

- 是否请求到了预期的地址；
- 查询参数和路径参数是否正确；
- 请求头和身份认证是否生效；
- 请求体格式和内容是否正确；
- 响应状态、响应体和响应头是否符合预期；
- 实际耗时和返回大小是否异常。

调试是验证单条请求的快速方式。需要长期重复执行、多人协作或纳入报告时，应将接口保存为测试用例。

## 5. 工具箱的 cURL 解析与运行

### 5.1 适合什么时候使用

当你已经从浏览器开发者工具、文档或其他系统拿到一条 cURL 命令，只想快速确认它能否正常请求时，可以使用工具箱的 cURL 解析。

它适合：

- 检查一条 cURL 命令包含哪些请求信息；
- 快速复现一个请求；
- 对比请求前后的结果；
- 在保存正式接口前先验证命令是否可用。

### 5.2 操作步骤

1. 把完整的 cURL 命令粘贴到输入区域；
2. 点击“解析 cURL”，确认请求方法、地址、参数、请求头和请求体；
3. 确认无误后点击“运行接口”，会直接开始请求并打开结果窗口；
4. 运行后默认定位到“响应结果”的“响应体”；
5. 根据需要切换到请求信息或响应头，并使用复制按钮复制内容。

没有执行过、执行失败或暂时没有返回内容时，响应区域仍然会展示，并提示“暂无响应”。这表示当前没有可展示的服务端响应，不代表请求信息丢失。

### 5.3 运行窗口展示什么

请求信息包括：

- 请求地址；
- 查询参数；
- 路径参数；
- 请求体；
- 请求头。

响应结果包括：

- 响应体；
- 响应头。

请求体、请求头、响应体和响应头都支持复制。响应体会尽量按易读的格式展示；无法识别为结构化内容时，按原始文本展示。

### 5.4 与正式接口测试的关系

cURL 工具运行只用于快速验证，不会自动创建项目接口、测试用例或执行记录。确认命令可用后，如果需要持续维护，应回到项目中保存为接口或测试用例。

## 6. 把接口整理成测试用例

测试用例是在接口基础上的可重复测试。除了基本请求信息，还可以配置：

- 测试数据和参数集；
- 前置或后置脚本；
- 结果断言；
- 需要提取并传给后续请求的内容；
- 运行时使用的环境。

新建用例时，系统会提供一条默认的业务结果检查：当响应体中存在业务编码时，默认检查其是否为 200。这个检查可以按实际接口调整、关闭或增加其他断言。没有启用断言时，接口调试、单条用例和执行集统一使用 HTTP status code 判断成功：`2xx` 为成功，其他状态为失败。

需要注意两种状态：

- HTTP 状态是网络请求本身的结果；
- 业务编码是接口返回内容里的业务结果。

启用断言时，用例是否通过以断言结果为准；没有启用断言时，以 HTTP status code 为准。业务接口如果使用固定的 HTTP 状态承载业务结果，应通过断言补充业务判断。

## 7. 参数集与批量测试

参数集适合验证同一个接口在不同输入下的表现，例如不同账号、订单、权限或边界值。

使用方式：

1. 创建参数集并录入多组数据；
2. 在测试用例中选择参数集；
3. 运行用例或执行集；
4. 在结果中查看每组数据的执行情况。

运行时可以使用用例自身的参数，也可以叠加执行时传入的参数。若同名参数同时存在，以当前执行场景中更具体的值为准。

删除参数集不会删除用例本身，但用例会失去对应的参数化数据。删除前请先确认是否仍有执行集依赖它。

## 8. 执行测试与查看报告

### 8.1 单条执行

适合验证一条接口或一个用例。执行前选择环境，必要时选择参数集，然后发起执行。

### 8.2 执行集

适合一次执行多条用例。可以配置：

- 执行哪些用例；
- 使用哪个运行环境和参数集；运行环境为必填项，项目未配置环境或当前未选择环境时不能保存执行集，提示“请配置或者选择运行环境”；
- 用例之间按顺序执行还是并行执行；
- 失败后是否重试；
- 是否在前置条件失败时停止后续用例。

接口调用说明中，运行环境字段即使在请求结构中显示为可选，也不代表业务上可以省略；新建和编辑执行集时必须提供当前项目中有效的运行环境。

批量执行前，建议先单独调试关键接口，避免把地址、认证或请求数据错误带入整批执行。

### 8.3 报告内容

报告用于回答三个问题：执行了什么、结果怎样、失败在哪里。

通常可以查看：

- 总体通过、失败和跳过数量；
- 每条用例的执行状态和耗时；
- 实际请求参数、请求体和请求头；
- 实际响应体和响应头；
- 断言、脚本和错误信息；
- 需要进一步处理的失败用例。

报告中的时间统一按北京时间展示。失败信息以服务端返回的中文提示为准；同一个错误不会重复弹出多次提示。

报告详情按用例展开。展开后，用例标题会在详情区域滚动时保持可见；响应体等较长内容在响应区域内部滚动，不带动整个页面无限增高。

### 8.4 清空项目数据

在项目数据看板右上角可以打开“清空项目数据”，按需选择环境、接口、用例、参数集、执行集和测试报告后确认清理。系统会先展示各模块及其关联数据的数量，再经过二次确认执行；清理采用软删除，已清理数据不会在当前项目业务页面展示。

在清空弹窗中，选择“接口”会自动同时选择“用例”，且“用例”不能单独取消；取消“接口”时会同步取消“用例”。如果不清理接口，仍可以只选择“用例”单独清理。接口删除会级联软删除关联用例和执行项。用例数量按实际清理的有效用例统计；“已加入执行集”按去重后的用例数计算，同一个用例加入多个执行集只计算一次。清理成功提示会展示实际清理的用例数量。

该操作属于高风险项目级操作，仅超级管理员可清空全部项目，私有项目创建人可清空本人项目；公开项目创建人、管理员和普通用户不可操作。具体权限以[权限说明](./权限说明.md)为准。

## 9. AI 辅助能力

### 9.1 批量生成测试用例

可以针对已有接口批量生成测试用例，也可以在接口用例页面针对当前单个接口生成。生成前需要选择范围和模型，生成后先预览，再决定保存哪些结果。保存阶段会按实际请求意图跳过与已有用例或本次结果重复的内容，名称冲突只追加后缀，不覆盖已有用例。

AI 生成结果中的用例名称和描述编辑框均限制为 50 个字符，并显示字数提示。接口编辑弹窗中的接口名称和描述也均限制为 50 个字符，并显示字数提示。生成失败或部分失败时，弹窗会展示接口级失败原因；失败明细过多时仅明细区域滚动，顶部失败提示和底部操作按钮保持可见。

生成结果可能需要根据真实业务补充：

- 正常场景和异常场景；
- 权限、边界值和必填项检查；
- 断言内容；
- 接口之间的数据传递关系。

模型不可用或调用失败时，需要人工选择其他可用模型后重新操作；系统不会静默切换模型，也不会把未确认的结果直接保存。

## 10. 定时执行与通知

需要周期性巡检时，可以为执行集配置定时任务，并选择成功或失败时是否通知相关人员。

配置时应确认：

- 执行集内容已经稳定；
- 使用的环境不是临时调试环境；
- 认证信息在任务运行时仍然有效；
- 通知对象能够处理失败结果。

定时任务只负责按计划执行已有内容，不会自动修改接口或测试用例。

## 11. 权限与安全边界

- 查看、编辑、调试、执行和管理权限可以不同；
- 项目创建者和管理员负责项目内的维护与授权；
- 普通成员只能在被授权范围内操作；
- 公开项目便于协作，但不应放入真实敏感信息；
- 外部请求可能访问真实服务，执行前要确认地址、环境和认证信息；
- AI 生成或导入的内容必须经过人工检查后再保存或执行。

项目权限和各类操作的详细限制，以 [权限说明](./权限说明.md) 为准。

## 12. 当前使用边界

- cURL 工具运行用于快速验证，不自动沉淀为项目资产；
- AI 生成结果必须预览和确认，不自动保存或执行；
- 场景编排、复杂跨接口流程等能力按页面当前提供的范围使用；
- 业务断言需要根据实际接口约定配置，系统不会替用户推断全部业务规则；
- 服务不可用、地址错误或认证失效时，页面只能展示错误信息，不能替代服务端修复问题。

## 13. 页面使用约定

- 查询条件需要点击查询按钮后才生效；
- 数据较多时使用分页，默认每页 10 条；
- 表格中的长内容可在详情中查看，页面不会因为长文本整体横向滚动；
- 删除和可能影响已有测试结果的操作会要求再次确认；
- 成功或失败提示以服务端返回的信息为准；
- 页面内容区域独立滚动，避免整页跟着表格一起滚动。
